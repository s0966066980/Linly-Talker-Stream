LLM 尚未完成全文時即可播放已確認的語意片段；插話後舊 token、片段、音訊與影格會在跨層 generation fence 被拒絕。

每個 delta、片段、音訊與影格都攜帶 turn_id、generation 與 sequence，取消後立即失效。

為什麼預設仍是 false？

Edge TTS＋MuseTalk 已完成正式驗證，但其他 TTS／Avatar 尚未逐一通過相同 50 回合 SLO。功能旗標保留跨引擎回退，不代表主力串流仍未實作。

目前可靠管線的模組邊界

VoiceTurnSession 擁有輪次；src/server/reply_streaming/ 封裝 producer、語意切片、turn context、背壓、circuit breaker、指標與 soak report。

VoiceTurnSession
├── ReplyProducer
├── SemanticFragmenter
├── BoundedSpeechChannel
├── TurnContext / TurnEnvelope
├── ReplyCircuitBreaker
└── TurnMetrics / SoakReport

回合協調留在既有 VoiceTurnSession，可靠性能力集中於 src/server/reply_streaming/，避免把協議散落到每個引擎 adapter。

ReplyProducer

在 worker thread 讀取同步 chat_stream，以 thread-safe bridge 導入 asyncio；每次交付前後都驗證取消狀態。

SemanticFragmenter

以強／弱標點和 24／32 字無標點門檻形成可播片段，避免逐字電子音與過長首句等待。

BoundedSpeechChannel

以待播媒體時間計算債務；2 秒停止接納、降回 1 秒才恢復，將背壓傳回 LLM producer。

Generation fence

插話時使舊 generation 失效；文字、TTS chunk、MuseTalk batch 與 WebRTC frame 在輸出邊界再次驗證。

Playback commit

第一個非靜音 WebRTC 音訊幀才提交字幕與 history，確保畫面與使用者真正聽到的內容一致。

目前已接入

  • BaseLLM.chat_stream 已提供 token 串流。
  • SemanticFragmenter 處理強／弱標點與長無標點回答。
  • bounded channel 以媒體債務施加背壓。
  • turn_id / generation / sequence 貫穿輸出邊界。
  • 播放 commit 決定字幕與已播 history。
  • WebRTC 以音訊主時鐘輸出並量測 A/V。
契約目前實作保證主要驗證
強分隔符。！？；.!?;非空片段可立即送出中英混合、連續標點
弱分隔符，、：, :，至少 12 字降低首音延遲而不把語音切碎短問句、列舉、token 邊界
無標點保底24 字找安全界限，32 字強制切片模型長時間不吐標點仍能開口英文單字、數字、URL
媒體背壓高水位 2 秒、低水位 1 秒所有待播資料維持有界LLM 快、TTS／GPU 慢
輪次隔離turn／generation／sequence envelope取消後舊資料不能 commit插話、失敗、重連
字幕與 history首個非靜音音訊幀後 commit只記錄真正已播放的內容取消、重試、事件亂序

只開啟分句 callback 並清除 queue

這種作法無法涵蓋 executor 取消、下游 batch、播放 commit 與 generation 隔離，因此未作為正式架構。

狀態：已排除原因：取消邊界不完整

VoiceTurnSession ＋可靠串流模組

保留既有引擎 adapter，由獨立模組提供 producer、切片、媒體背壓、取消柵欄、播放提交、指標與 circuit breaker；主力組合已通過 50 輪 SLO。

狀態：已交付主力 SLO：通過預設：關閉

所有 LLM／TTS adapter 改成原生 async stream

在跨引擎與多人 GPU 排程成為正式需求時再評估；目前優先補齊 persistent Edge worker、資源界限與跨引擎 SLO。

狀態：未排程前置：跨引擎量測

主力組合已通過的驗收條件

首句必須早於完整回答
測試 LLM 尚未結束時，第一個 TTS segment 已送出；記錄 LLM TTFT、首句提交與首音訊延遲。
插話後零舊音訊
取消回合後，即使 executor 還在退 token，任何舊 segment 或 audio frame 都不能抵達 Avatar 輸出。
分句順序與完整性
所有可見文字只增不漏、segment 序號連續，最後拼接內容與完整 LLM 回覆一致。
反壓與錯誤恢復
TTS 慢時佇列不無限成長；任一引擎失敗會送出單一 error，清理資源並重新開啟收音 gate。

05 · Recorded decisions

已落地的產品與架構選擇

後續引擎接入必須遵守相同契約，並重跑同一組 SLO 與取消情境。

首句偏快，還是語意偏完整？

太短會像機器逐片念字，太長又失去串流價值。

已採用：強／弱標點＋24／32 字無標點保底

Markdown 要不要直接念？

畫面需要保留 Markdown，但 TTS 不應朗讀星號、網址與程式碼符號。

已採用：顯示文字與可發音文字分離

插話要多徹底？

只清 TTS queue 不夠；LLM worker 與已產生音訊也必須失效。

已採用：turn_id／generation 端到端取消柵欄

先正式支援哪些組合？

所有引擎一次改完風險高，必須以同一驗收門檻逐步擴充。

目前：Edge TTS＋MuseTalk；其他組合相容但未完成相同 SLO

目前結論

可靠串流架構已落地並通過主力實機門檻。功能旗標仍預設關閉，直到跨引擎、長時間真人與正式部署驗收完成後再評估全面啟用。
