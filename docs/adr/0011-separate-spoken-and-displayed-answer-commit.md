# 分開記錄已播語音與已顯示看板項目

按需看板回答由數字人口述摘要，具體項目由控制台與舞台顯示。使用者已確定需要針對看板內容追問，因此正式整合方向是將已播語音與已顯示看板項目分開記錄，共同提供後續對話上下文；將所有內容塞進 `played_text` 會破壞其「已出聲」的意義，而僅保留語音則無法理解「第二點詳細說明」。

此提案記錄已確認的產品方向，尚未批准或完成正式實作。現行 [ADR 0007](0007-stream-replies-with-turn-isolation-and-audio-clock.md) 與 [ADR 0010](0010-console-rest-state-follows-turn-commit.md) 的語音提交保證繼續有效；視覺內容的提交事件與顯示確認機制需在整合設計時補足，不能將發送、顯示、閱讀混為一談。

## Consequences

- 口語／看板分流在後端、語意切片與 TTS 入列之前完成，串流與舊有回覆模式均須涵蓋。
- 已顯示的完整項目可供追問；插話後保留已顯示內容，尚未顯示的舊輪次內容丟棄。看板收合只改可見性，清空對話才移除該場對話的看板上下文。
- 控制台與舞台須對應同一場對話，不能沿用目前每次 `/offer` 建立獨立會話後就假設跨頁同步。訂閱、觀看端確認、重送去重與重連由正式會話契約負責。
- 看板失敗保留可用摘要與已顯示項目並支援重試；不自動把全部細節送入 TTS。
- [需求與原型](../../.scratch/answer-board/spec.md) 可驗證交互行為；固定情境的瀏覽器模擬不能代替實際語音、模型協定與 WebRTC 驗證。
